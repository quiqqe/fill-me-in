## What was wrong

nginx doesn't run PHP itself. It passes PHP requests to a separate PHP-FPM service, which the config calls `php`. To reach it, nginx has to turn the name `php` into an IP address, like asking a phone book.

The problem was **when** nginx looked that name up. It did it once, at startup or reload, and then kept using the same IP. When you recreate the php container, Docker usually gives it a **new IP**. nginx kept sending requests to the old one, where nothing was listening anymore, so the site returned **502 Bad Gateway**. The only fix was to reload nginx so it would look the name up again.

## What the old config tried

The config had a common workaround:

```nginx
set $php_fpm php:9000;
fastcgi_pass $php_fpm;
```

Putting the address in a variable makes nginx look the name up again during requests, not only at startup. It's a hack, though: it skips nginx's normal "upstream" mechanism (the named group of backend servers it forwards to), and it's easy to break.

## What I changed

1. **Removed the variable trick** (`set $php_fpm ...`).
2. **Defined PHP-FPM as a proper `upstream` block** with two options:
   - `zone`: gives the upstream a small piece of shared memory, which nginx needs before it can update the server's address while running.
   - `resolve` on the `server php:9000` line: tells nginx to keep re-checking what IP `php` points to while it runs.

resolver 127.0.0.11 valid=1s;   # Docker's built-in DNS
