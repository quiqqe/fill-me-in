Знакомо. Даёшь агенту задачу, отвлекаешься на десять минут, возвращаешься и читаешь:

> Убрал `set $backend`, перевёл на upstream с `zone` и `resolve`, `valid=1s`. Теперь пересоздание app не требует reload.

Каждое слово знакомо. Смысла ноль. Агент всё это время был в комнате: читал файлы, отбросил две гипотезы, как-то называл вещи по ходу. И пишет так, будто ты был рядом.

Fill Me In заставляет агента писать для того, кто только что вошёл.

## До / после

Тот же фикс с Fill Me In:

> **Суть:** nginx теперь сам замечает, что контейнер app пересоздали, и его не нужно перезапускать.
>
> **Как это устроено.** nginx обращается к контейнеру app по имени `app`, а в IP-адрес это имя переводит DNS Docker. Пересоздали контейнер — IP может смениться, и nginx, запомнивший старый адрес, шлёт запросы в пустоту. Новый блок `upstream` с `resolve` заставляет nginx переспрашивать DNS раз в секунду (`valid=1s`).
>
> ```
> запрос → nginx → upstream backend → DNS: «app = ?» (раз в 1 с) → контейнер app
> ```
>
> **Пример.** Деплой пересоздаёт app, IP меняется с .5 на .7, и не позже чем через секунду nginx шлёт запросы на .7. Раньше nginx пришлось бы перезапускать руками.

Не длиннее ради длины. Длиннее ровно на тот контекст, который ты пропустил. Настоящие пары ответов из прогона эвалов: [examples/](examples/).

## Цифры

Шесть сценариев, где агент отчитывается о работе, которую ты не видел. Каждый прогнан 4 раза с плагином и без, оценивал судья Sonnet по одному вопросу: *поймёт ли человек, не видевший работы, что было не так, почему и что дальше?*

| | с плагином | без |
|---|--:|--:|
| средняя оценка | **0.85** | 0.74 |
| прогонов, прошедших все критерии | **19/24** | 15/24 |
| слов в ответе | 380 | 251 |

Выигрыш там, где обычный ответ скуп (нестабильный тест, «не понял» после короткого ответа). В трёх кейсах модель и так объясняет хорошо, и обе стороны получают 1.00. Ответы длиннее примерно наполовину. Честный промах: когда пользователь эксперт, обе стороны всё равно накидывают лишних оговорок. Набор маленький, по одному сообщению — методика, таблица по кейсам и ограничения в [evals/results](evals/results/README.md). Повторить: `claude plugin eval . --judge-model sonnet`.

## Как это работает

Две части в одном плагине.

**Правило на каждый ответ.** Хук `SessionStart` (а также после `/clear` и сжатия контекста) загружает его, а напоминание в одну строку едет с каждым твоим сообщением, чтобы другие инструкции его не заглушили:

```
1. Сначала ситуация     → что происходило, что агент нашёл
2. Потом вывод          → что, почему, что это значит для тебя
3. Без личного контекста → «тот баг», «вторая гипотеза» объяснены или убраны
4. Конкретика           → «запрос X вернёт Y, потому что Z»
5. Глубина по тебе      → по теме, по твоим словам, а не по ощущению агента «это очевидно»
```

Глубину агенты обычно угадывают неправильно, поэтому она берётся из разговора, а не из догадки:

| Ты… | Агент… |
|---|---|
| сам используешь термины темы, поправляешь по существу | пропускает азы |
| спрашиваешь, что значит термин, пишешь «не понял» | объясняет механизм и держит этот уровень по теме |
| никак не показываешь | объясняет: лишняя фраза дешевле непонятного ответа |

**`/fill-me-in`, если ответ всё же не зашёл.** Агент находит невидимый тебе контекст, на который опирался, перепроверяет ключевые факты по источнику, а не по памяти, и перерассказывает: суть в одной строке, механизм, пример по шагам, что из этого следует. `/fill-me-in <место>` разбирает только это место.

## Уживается с «пиши короче»

Стоят [ponytail](https://github.com/DietrichGebert/ponytail), [caveman](https://github.com/JuliusBrussee/caveman) или своё правило «максимум три строки»? Оставь. Fill Me In говорит агенту: пусть они режут код, повторы и вежливость, но не контекст, причины и механизм. Ты поставил его, чтобы понимать ответы, поэтому в объяснениях он главнее. Прямая просьба в сообщении («только код») главнее обоих.

## Установка

### Claude Code

```
/plugin marketplace add quiqqe/fill-me-in
/plugin install fill-me-in@quiqqe
```

Начинает работать со следующей сессии.

### Только skill, в любом агенте

Один `/fill-me-in`, без постоянного правила — для агентов, которые понимают `SKILL.md`:

```bash
npx skills add quiqqe/fill-me-in
```

### Удаление

```
/plugin uninstall fill-me-in@quiqqe
```

<details>
<summary><strong>Почему плагин, а не просто skill?</strong></summary>

Skill загружается, только когда агент решит, что задача под него подходит. «Пиши понятно» нужно в каждом ответе, и как skill оно промахнулось бы ровно на быстрых ответах, где контекст и теряется. Плагин через хук загружает правило при каждом старте сессии и при этом даёт `/fill-me-in` про запас.

</details>
